Les couches d'un site web, expliquées pas à pas

Un site, un CMS ou une web app s'empilent en couches. Chaque couche répond à une seule question et s'appuie sur la couche du dessous. Cette page te fait parcourir ces couches dans l'ordre, puis te propose de vérifier ce que tu as retenu.

1Ce qui se passe quand tu tapes une adresse

Avant de parler de couches, suis le trajet d'une page. Clique sur les étapes ou utilise les boutons.

2Les couches une par une

Les couches se répartissent en trois zones : front-end dans le navigateur, back-end sur le serveur, infrastructure sous le serveur. Clique sur une couche pour afficher son rôle.

3Tes outils dans la pile

Les couches restent les mêmes d'un projet à l'autre. Seul l'outil qui occupe chaque couche change. Choisis une pile pour voir qui fait quoi. Les bandes hachurées signalent une couche absente.

4Quatre mots à distinguer

La confusion entre « CMS » et « framework » vient de là. Ces quatre mots décrivent quatre niveaux de prise en charge, du plus libre au plus clé en main.

🔤

Langage

La langue dans laquelle on écrit les instructions.

PHPJavaScriptPython
Test : on peut « écrire en » PHP.
🧰

Bibliothèque

Une boîte d'outils. Ton code l'appelle quand il en a besoin.

jQueryChart.js
Test : tu restes maître du plan, tu empruntes un outil.
🏗️

Framework

Une charpente imposée. Tu écris ton code à l'intérieur, selon ses règles.

SymfonyBootstrapReact
Test : sans développeur, il ne produit rien d'utilisable.
🏠

CMS

Une application finie, avec un back-office. On la configure plus qu'on ne la programme.

WordPressDrupal
Test : un rédacteur peut publier un article le jour de l'installation.
Liberté totale, tout à écrire
Clé en main, moins de liberté

Le cas de Bootstrap

Bootstrap est un framework, mais un framework CSS. Il fournit une grille, des boutons et des formulaires déjà stylés. Il agit seulement sur l'apparence (couche F2), avec quelques composants JavaScript (couche F3). Il ne stocke aucun contenu et n'a pas de back-office. Tu peux donc l'utiliser dans un thème WordPress, dans un thème Drupal ou sur une page HTML seule.

5Les architectures : où se fabrique la page

Une architecture décrit l'endroit où la page est assemblée. Les couches restent les mêmes, mais leur répartition change.

Monolithique

Navigateur ← HTML ← CMS + BDD

Le CMS assemble la page complète sur le serveur. C'est le fonctionnement d'un WordPress ou d'un Drupal classique.

Headless

Navigateur ← React ← JSON ← CMS

Le CMS fournit seulement les données, via une API. Un front-end séparé les met en page.

Site statique

Générateur → fichiers HTML → Navigateur

Un générateur (Hugo, Astro, Jekyll) fabrique toutes les pages à l'avance. Le serveur n'a plus de base de données.

SaaS ou no-code

Toi → éditeur visuel → plateforme

La plateforme (Wix, Webflow, Shopify) gère toutes les couches serveur. Tu agis seulement sur le contenu et le design.

Web app (SPA)

App JS dans le navigateur ⇄ API

Une application JavaScript tourne dans le navigateur et échange des données sans recharger la page, comme Gmail ou Notion.

Application mobile

App iOS / Android ⇄ API ⇄ back-end

Le front-end est natif (Swift, Kotlin) ou multiplateforme (Flutter, React Native). Le back-end peut servir aussi le site.

6Teste-toi

Pour chaque outil, choisis la couche qu'il occupe. L'explication s'affiche après ta réponse.

7Les outils transversaux

Certains outils ne forment pas une couche. Ils servent toutes les couches à la fois.

Versionnement

Git, GitHub, GitLab. Ils gardent l'historique de chaque modification du code.

Déploiement (CI/CD)

GitHub Actions, GitLab CI. Ils testent et mettent en ligne le code automatiquement.

Dépendances

Composer pour PHP, npm pour JavaScript. Ils installent les bibliothèques et frameworks.

API

REST, GraphQL. Elles font circuler les données entre deux couches ou deux logiciels.

Sécurité

HTTPS, pare-feu, sauvegardes, mises à jour. Chaque couche peut avoir une faille.

Mesure et SEO

Matomo, Google Analytics, Search Console. Ils mesurent l'audience et la visibilité.

À retenir

  1. Le front-end s'exécute dans le navigateur : HTML pour la structure, CSS pour l'apparence, JavaScript pour le comportement.
  2. Le back-end s'exécute sur le serveur : il lit la base de données et prépare la réponse.
  3. Un CMS (WordPress, Drupal) est une application finie. Un framework (Symfony, Bootstrap) est une charpente pour développeur.
  4. Drupal repose sur Symfony. WordPress n'utilise pas de framework.
  5. Pour situer un outil inconnu, demande-toi à quelle question il répond, puis cherche la couche correspondante dans la section 2.
