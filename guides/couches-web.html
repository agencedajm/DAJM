Guide pour débutant

Comprendre comment un site web est fabriqué

Tu entends parler de WordPress, Drupal, Symfony, Bootstrap, JavaScript… et tu ne sais pas qui fait quoi. C'est normal : ces outils ne font pas la même chose, et personne ne te l'a expliqué dans l'ordre.

Ce guide utilise une seule image du début à la fin : un site web fonctionne comme un restaurant. Lis les chapitres dans l'ordre. Chacun prend deux minutes.

1. Le restaurant 2. Une commande 3. La salle 4. La cuisine 5. Le bâtiment 6. Range tes outils 7. Quatre mots 8. Différents restaurants 9. Teste-toi Lexique
Chapitre 1

Un site web, c'est un restaurant

Un restaurant a trois parties. Un site web aussi.

🍽️ La salle = le front-end
C'est ce que le client voit et touche : les tables, la déco, le serveur qui prend la commande. Sur le web, c'est la page qui s'affiche sur ton écran.
👨‍🍳 La cuisine = le back-end
Le client ne la voit jamais. C'est là qu'on prépare les plats et qu'on range les ingrédients. Sur le web, c'est un ordinateur à distance, appelé serveur, qui prépare la page.
🏢 Le bâtiment = l'infrastructure
Les murs, l'électricité, l'adresse dans la rue. Sur le web, c'est la machine louée chez un hébergeur et l'adresse du site.
À retenirFront-end = ce que tu vois. Back-end = ce qui travaille en coulisses. Infrastructure = ce qui fait tenir le tout.

Chapitre 4

La cuisine : le serveur et ce qui tourne dessus

La cuisine prépare la page avant de l'envoyer dans ta salle. Elle a cinq postes. Lis-les dans l'ordre où la commande les traverse.

① Le serveur web : celui qui reçoit les commandes

Il reçoit la demande du visiteur et la transmet au bon endroit. Il renvoie aussi la page finie.

Au restaurant : le passe, le comptoir entre la salle et la cuisine.
ApacheNginx

② Le langage : la langue des recettes

Les programmes de la cuisine sont écrits dans une langue que l'ordinateur comprend. Pour WordPress, Drupal et Symfony, cette langue est le PHP.

Au restaurant : la langue dans laquelle les recettes sont écrites.
PHPPythonJavaScript (Node.js)

③ Le framework : la cuisine professionnelle équipée

Un framework fournit tout l'équipement de base : fours, plans de travail, règles d'hygiène. Un cuisinier (un développeur) doit quand même venir cuisiner.

Au restaurant : une cuisine pro vide, prête à l'emploi, mais sans chef.
SymfonyLaravelDjango

④ Le CMS : le restaurant clé en main

Un CMS est un programme déjà fini. Il a un back-office : une interface où tu changes les textes et les images sans écrire de code.

Au restaurant : une franchise prête à ouvrir. Le patron change la carte lui-même, sans être cuisinier.
WordPressDrupalJoomlaPrestaShop

⑤ La base de données : la chambre froide

C'est là que tout le contenu est rangé : les textes, les comptes, les commandes. Le CMS vient y chercher ce dont il a besoin à chaque visite.

Au restaurant : la chambre froide où attendent les ingrédients.
MySQLMariaDBPostgreSQL
Le piège classique : CMS ou framework ?Un framework, c'est une cuisine équipée : il faut un chef pour cuisiner. Un CMS, c'est un restaurant entier qui tourne déjà : tu changes la carte toi-même. Drupal est un CMS construit avec des outils de Symfony. Il a donc été installé dans une cuisine Symfony. WordPress, lui, a construit sa propre cuisine.

Chapitre 8

Il existe plusieurs sortes de restaurants

Les postes restent les mêmes. Ce qui change, c'est qui les tient et où le plat est préparé.

🍲

Le restaurant classique

La cuisine prépare chaque plat à la commande et l'envoie en salle.

Sur le web : WordPress ou Drupal fabriquent chaque page à la demande.

🥪

Les plats préparés à l'avance

Tout est cuisiné le matin. On sert sans cuisiner. C'est très rapide, mais la carte change peu.

Sur le web : un site statique (Hugo, Astro). Les pages sont fabriquées une fois pour toutes.

🏬

Le stand en centre commercial

Le centre fournit le local, la cuisine et le ménage. Tu choisis la déco et la carte.

Sur le web : Wix, Webflow, Shopify. La plateforme gère toute la cuisine à ta place.

🚚

La cuisine centrale qui livre

Une seule cuisine prépare les plats. Elle livre plusieurs salles différentes.

Sur le web : le « headless ». Le CMS envoie seulement le contenu. Un site et une appli mobile l'affichent chacun à leur façon.

Petit lexique

Front-end
Tout ce qui s'affiche et s'exécute dans ton navigateur. La salle.
Back-end
Tout ce qui s'exécute sur le serveur. La cuisine.
Serveur
Un ordinateur à distance, allumé en permanence, qui fabrique et envoie les pages.
Navigateur
Le logiciel qui affiche les sites : Chrome, Safari, Firefox.
Back-office
L'espace d'administration d'un CMS, où tu modifies le contenu sans coder.
Thème
Le « décor » d'un CMS : son HTML, son CSS et son JavaScript.
Extension (plugin, module)
Un ajout qui donne une nouvelle fonction à un CMS, comme un formulaire de contact.
API
Un guichet par lequel deux logiciels s'échangent des données. Le passe-plat entre deux cuisines.
Git, GitHub
Les outils qui gardent l'historique de chaque modification du code. Le cahier où l'on note chaque changement de recette.
Stack (pile)
La liste des outils choisis pour chaque poste d'un projet. Par exemple : Drupal + PHP + MySQL + Bootstrap.

Les 5 phrases à retenir

  1. Un site, c'est une salle (front-end), une cuisine (back-end) et un bâtiment (infrastructure).
  2. Dans la salle : HTML pour le contenu, CSS pour l'apparence, JavaScript pour les réactions.
  3. Bootstrap est du CSS prêt à l'emploi. Il ne travaille que dans la salle.
  4. Symfony est une cuisine équipée (framework). WordPress et Drupal sont des restaurants clé en main (CMS).
  5. Drupal est bâti sur des outils Symfony. WordPress, non.
